## 一、一句话定位

v1.0.1 = **多用户会话正确性** + **会话管理体验**（重命名/分组/父子）+ **上下文工程**（compact/命令）+ **本地模型兼容**（Ollama）。

## 三、需求 → 批次映射

### B1 会话归属与安全地基（需求 3）—— 一切的地基

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 创建归属 | `/chat/session`、`/session/active`、Agent 流式建会话：`resolveCurrentUserId()`（与 T7 配额同源）穿参到 `sessionService.createSession`，user_id 不再为 NULL | 新建会话 DB user_id = 当前账号 |
| T1.2 列表隔离 | `/chat/sessions` 改走 `getSessionsByUserId(currentUser)`（方法已存在，接线） | 账号 A 看不到 B 的会话 |
| T1.3 操作闸门 | clear/delete/详情/messages 校验归属（owner 或 ADMIN，复用 T7 的 403 模式） | B 对 A 的会话 clear/delete/读消息 → 403 |
| T1.4 存量迁移 | 开发库 `user_id IS NULL` 全部刷为 admin(id=1)（**决策点 D1**） | 无 NULL 归属会话残留 |

### B2 会话管理（需求 2）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 重命名 | `PATCH /chat/session/{id}/title`（写 remark，复用已预留字段+前端展示链路）；列表项 hover 出重命名入口 | 重命名后侧栏即时更新，刷新保持 |
| T2.2 分组 | `ALTER TABLE chat_session ADD COLUMN IF NOT EXISTS group_name VARCHAR(100)`（init.sql 同步）；列表按组聚合 UI（组头+折叠） | 会话可归入分组、分组可折叠、未分组归入「默认」 |
| T2.3 分组管理 | 分组重命名/删除（仅改 group_name，不动会话） | 删组后会话回落「默认」 |

### B3 斜杠命令 + 上下文压缩（需求 6 + 5）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T3.1 命令框架 | **交互形态（老板拍板口径）**：输入框输入 `/clear` `/reset` `/compact` 回车后系统执行，**结果以流式形态输出到聊天区**。`/clear`=清当前会话历史（复用 clearSession，流式输出清理结果）；`/reset`=流式提示后新建会话并切换；`/compact`=新增后端 SSE 端点，摘要生成过程 delta 流式推送、完成后写库并流式输出统计。前端输入 `/` 弹补全提示 | 三命令均回车生效，聊天区可见流式执行过程与结果 |
| T3.2 压缩后端 | `chat_session` 加 `context_summary TEXT`；`chat_message` 加 `compressed SMALLINT DEFAULT 0`；compact = 把未压缩旧消息丢当前激活 chat 模型生成摘要 → 写 context_summary + 标记 compressed=1；构建 LLM 上下文改为 `context_summary + 最近 N 条未压缩原文` | compact 后长会话继续对话，模型仍知道早期内容；token 占用显著下降 |
| T3.3 主动 compact | 会话 UI「压缩上下文」按钮 + `/compact` 命令 | 点击/命令后提示压缩结果（压缩 X 条，摘要 Y tokens） |
| T3.4 自动 compact | 发送前估算 token（复用 estimateTokens）超过阈值自动触发 T3.2；**设置页新增「对话设置」区**：autoCompact 开关（默认开）、阈值 tokens（默认 8000）、保留最近条数（默认 20） | 构造长会话超阈值，下一轮发送前自动压缩且对话不中断 |

### B4 父子会话（需求 4）—— 对齐 OpenClaw 子代理语义

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T4.1 数据模型 | `chat_session` 加 `parent_session_id VARCHAR(64)`；详情/列表 DTO 带 parent 标记 | 字段就位 |
| T4.2 派生流程 | 会话列表/会话内「派生子会话」：子会话克隆父 systemPrompt + 父会话 context_summary（无则近 N 条消息的即时摘要）作为起点；父子独立演进 | 派生后子会话可独立对话；父会话不受影响 |
| T4.3 树形展示 | 会话列表支持 父→子缩进树（配合 B2 分组：同组内树形） | 树形正确、折叠可用 |
| T4.4 自动回传（**升级：老板拍板进 v1.0.1**） | 子会话 done 时后端自动生成结果摘要（finalAnswer + toolsUsed），以 system 角色消息（前缀「[子会话结果]」）写入父会话上下文，父会话后续对话可自然引用；防循环：回传只向上传一层；前端父会话展示「来自子会话」标记消息 | 子会话完成后父会话下一轮回复能引用子会话结论，无需人工操作 |

### B5 Ollama 兼容（需求 1）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T5.1 维度弹性化 | `document_chunk.embedding` 改 `vector`（无固定维；无向量索引，全表扫不变）；应用层闸门：检索前校验 queryVec 维度与库内 `dimension` 列一致，不一致给出「需重建索引」明确报错 | 换 embedding 模型不再需要 ALTER TABLE |
| T5.2 切换引导 | 配置中心切换/保存 embedding 配置且维度变化时，提示「需清空并重建知识库向量」+ 一键清空入口 | 引导文案出现；一键清空后可重新索引 |
| T5.3 Ollama 预置 | vendor 下拉加 `ollama`（baseUrl 默认 `http://localhost:11434/v1`，mode 默认 text，key 占位提示）；文档 OLLAMA.md（chat+embedding 全本地部署指南） | 用 nomic-embed-text(768) 完成上传→索引→检索全链路 |
| T5.4 chat 验收 | vendor=ollama 配 qwen 系列跑通普通对话 + 智能模式（工具调用） | 两模式各一轮成功对话 |

依赖序：**B1 → B2 → B3 → B4**；B5 独立，可穿插但验收放最后（涉及清库重建向量，避免中途折腾）。

## 四、Non-Goals（本版明确不做）

- 自动摘要回传降级方案（已升级为自动回传进本版，见 T4.4）
- 会话分享/导出
- 向量索引（HNSW/IVFFlat）——数据量到需要时再建
- 多模态消息上下文压缩（只压文本链路）
- Ollama 的 /embeddings/multimodal 兼容（火山专用端点无本地对应物）

## 五、决策记录

| 日期 | 决策 | 依据 |
|---|---|---|
| 2026-10-28 | 重命名复用 remark 字段而非新加 title 列 | 字段已存在且前端展示链路已预留 remark 优先级，零迁移成本 |
