## B0 前置清理

### T0 学习示例模块迁回 learn 分支（0.5 天）
- **范围**：`ExamplesView.vue` + `ServiceController` + `AiServiceLayer`（及 example/ 子包）+ 相关路由/菜单项
- **做法**：跨分支复制不 cherry-pick（字节级，参照既有 cmd 重定向法）；learn 分支接入后验证 Day 示例可跑；develop 删除后全量编译 + 前端 build
- **验收**：develop 无示例残留（grep ServiceController/AiServiceLayer 零命中）；learn 分支示例页正常
- **注意**：`langchain4j.dayN.*` 开关随示例一起走，develop 的 yml 清掉对应块

### T1 品牌与包名重构（2~2.5 天，含技能地图同步）
- **包名**：`com.example.lc4j` → `com.gewu`；**执行手段**：脚本批量替换（Java 文件 UTF-8 without BOM，遵守字节级编辑规则，禁止 PS Get-Content 内存改写），含 mybatis mapper namespace / yml 引用；IDEA 仅作为人工复核工具非执行主体
- **模块名**：`lc4j-*` → `gewu-*`（Maven artifactId/目录名同批）；`database/langchain4j-kb-init.sql` → `database/gewu-init.sql`（文件名随品牌，本机开发库名 `langchain4j_kb` 保留不动）
- **旧坐标清扫**：重构后 `~/.m2` 内旧 `lc4j-*` 构件仍在，须删除或验证无解析残留（否则「改了没生效跑旧 jar」坑重现）
- **技能地图联动**：`java-ai-native-map` 技能中 lc4j 路径/包名/库名记录随重构失效，执行时经 skill_workshop 同步更新（作为 T1 交付物之一）
- **前端品牌**：页面标题「LC4J」→「Gewu · 格物」；logo 液态 blob → 几何「格」标（含单色 favicon），配色严格按 PRD §8.1 方案 B 令牌执行：`--accent #0ea5e9→#4F46E5` 等变量替换 + 渐变收敛 ≤3 处 + 毛玻璃仅留顶栏 + 状态色换固定语义值
- **风险控制**：重构单独 commit；编译 + 启动 + 登录 + 一轮对话 + 一次 RAG 检索冒烟全过才继续
- **验收**：`mvn clean compile` 全绿；`.m2` 无旧坐标残留；前端 `:root` 令牌与 PRD §8.1 一致；全局 grep `lc4j`（除 git 历史/CHANGELOG/技能历史记录）零残留

## B1 部署骨架（T2，3 天）

### T2 容器化交付全套（PRD F1）
- 后端 `Dockerfile`：多阶段构建（Maven 构建 → JRE 17 运行层），分层 fat jar 优化缓存
- 前端 `Dockerfile`：node 构建 → nginx 托管静态 + `/api` 反代配置
- `docker-compose.yml`：`gewu-server` + `gewu-web` + `gewu-db`（镜像 pgvector/pgvector:pg16）三服务，healthcheck + depends_on + 数据卷
- **命名规范**：镜像 `ghcr.io/<owner>/gewu-{server,web}`；部署库名默认 `gewu`（本机开发库 `langchain4j_kb` 保留不动，互不影响）
- `.env.example`：DB 密码/JWT 密钥/初始管理员密码/上传目录挂载
- init SQL 容器内自动执行（挂载 `database/` 到 `/docker-entrypoint-initdb.d/`）；**验证 bool→smallint / varchar→jsonb 两个 CAST 在干净库重跑无错**；init.sql 文件名以 T1 重构后为准（gewu-init.sql）
- **初始管理员引导**：种子 SQL 固定 admin 账号（BCrypt hash 按既有规则先验证再入库）+ 首登强制改密；初始密码注入 .env 或首启日志打印随机值（实现时定，DEPLOY.md 写清）
- **JWT 密钥安全**：.env.example 注释强提示生成随机值（`openssl rand -base64 48` 等），不交付默认密钥生产可用
- 上传文件目录挂载卷（知识库物理文件持久化）
- `docs/DEPLOY.md`：30 分钟部署文档（含 Windows Server / Linux 双场景）+ pg_dump 定时备份与恢复指引（数据库卷 + 上传文件卷，对应 PRD 非功能）
- **验收（按 PRD 用户旅程）**：干净目录 `docker compose up -d` → 初始管理员登录→强制改密→建普通用户 → 配模型前对话给明确报错 → 配模型 → 传文档 → RAG 对话成功；全程不看源码

## B2 核心配置（T3 → T4，5~6 天）

### T3 模型配置中心（PRD F2，3 天）
- **表**：`llm_provider`（id/name/provider_type=chat|embedding/endpoint/api_key_encrypted/models jsonb/enabled/created_at/updated_at）
- **范围含 embedding**：`VolcEmbeddingClient`/`VolcMultiModalEmbeddingModel` 同步改造为读配置中心——知识库索引与检索随配置生效，否则「换供应商零重编译」目标断裂
- **加密**：AES-256-GCM，密钥来自 env（`GEWU_ENCRYPT_KEY`），密文落库；key 永不出现在任何列表接口返回
- **动态生效**：新建 `ModelProviderService` 替换 LangChain4jConfig 静态构建——对话/agent/RAG 索引/检索各取模型处改走该服务（缓存 + 版本号失效）；**兼容性闸门：切换 embedding 模型后存量向量维度不匹配的处理策略随任务定（v1.0 允许「新索引用新模型、存量提示重建」文档化方案）**
- **前端**：Settings 页（Provider 列表/表单/连通性测试按钮，chat 测对话 + embedding 测向量维度）
- **兼容**：env 变量作为 fallback 初始 seed（首次启动导入）
- **验收**：网页配错 key → 对话明确报错；改对 key → 无重启即恢复；DB 内 key 为密文；embedding 配置变更后新上传文档索引正常
- **注意**：OpenAI 兼容协议一类先保证（volc/dashscope/deepseek/moonshot 均兼容）；thinking:disabled 等既有坑的参数处理迁入配置项

### T4 知识库格式与检索测试台（PRD F3，2~3 天）
- **格式**：docx（Apache POI）/ pdf（Apache PDFBox，文本层）解析接入现有分块管线；扫描件 pdf 明确报「无文本层」提示（OCR 属 v2）
- **测试台**：KnowledgeView 新增「检索测试」面板——输入问题 → 展示命中片段/相似度/所用文档，可调 topK 与阈值
- **验收**：四类文件（md/txt/docx/pdf）各传一个，索引→检索→Agent 引用全链路；测试台结果与 Agent ragHits 一致

## B3 产品收口（T5~T8，5~6 天）

### T5 Agent 模板与创建向导（PRD F4，2 天）
- 预置模板 3 个（知识库问答/客服接待/通用助手）：种子 SQL 含 systemPrompt/推荐参数/建议工具

- **验收**：3 分钟从模板创建可用 Agent 并完成一次带知识库引用的对话

### T6 用量报表（PRD F6，1.5 天）
- 管理端新页：按天/用户/Agent 三维度汇总 token 与调用次数（现有 token_usage/llm_call_log 聚合查询）
- 可选配额开关：配额参数（quota.enabled + 每用户日 token 上限）——现有 11 表无 sys_config 表，实现时二选一：新增 `sys_config` 键值表（支持网页改）或 env/yml 配置（零成本）；默认 env，超限明确报错（不做预扣）
- **验收**：报表数字与 SQL 直查一致；配额开关生效与关闭两态验证

### T7 二开文档（PRD F5，1.5 天）

- `docs/ARCHITECTURE.md`：模块划分图 + 请求链路图（开源 README 素材）
- **验收**：按教程独立实现 demo 工具编译运行成功（老板或外部朋友试读反馈）

## 验收与质量门（每批通用）

1. `mvn clean compile` + 前端 `npm run build` 全绿
2. 既有功能回归：登录 → 对话（流式）→ 知识库上传检索 → Agent 审批闭环冒烟
3. 核心链路集成测试随任务交付（审批闭环 / RAG 检索 / 配置中心优先），CI 保持绿色
4. 容器批次（B1 起）：`docker compose up` 干净库启动 + 冒烟
5. 涉 SQL 改动：init.sql 单文件真相源 + 幂等重跑 0 ERROR + 活库验签（既有规则）
6. commit 按关注点拆分；**改完不自动 commit，等老板确认**
