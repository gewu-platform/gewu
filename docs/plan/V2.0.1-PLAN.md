## 三、需求 → 批次映射

### B1 插件工具白名单生效（R3/T3.3 补齐）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 桥接过滤 | `McpClientHolder.connectAndBridge(serverName, endpoint, allowList)` 增加白名单参数：非空时只桥接清单内工具，其余跳过并日志记录 | 配置 `tool_allow=["read_file"]` 后，仅该工具进 ToolRegistry，其余被跳过且有日志 |
| T1.2 安装传参 | `PluginRegistryService.install()` 解析 `toolAllow`（JSON 数组）传给 C3 创建链路；空/解析失败=不限（保持现状行为） | 安装带白名单的插件，桥接数=白名单数；不配则全量桥接（向后兼容） |
| T1.3 前端配置 | 插件条目新增/编辑支持填工具白名单（逗号或 JSON 数组两种输入，后端归一） | 页面配置后安装生效 |
| T1.4 卸载一致性 | 卸载时按实际桥接过的工具注销（配合 T1.1 跳过逻辑，避免注销不存在的工具名告警） | 卸载无残留、无异常日志 |

### B2 Skill 目录可配置（R2/T2.5 补齐）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 配置项落地 | `application.yml` 的 `gewu:` 段新增 `skills.dir`（默认 `${GEWU_SKILLS_DIR:C:\Users\25333\.agents\skills}`），支持环境变量覆盖 | 改 env 后重启生效 |
| T2.2 运行时改目录 | `/api/settings/skills/dir`（GET 当前值 / POST 修改并立即重扫），ADMIN 限定；仅改运行态（不落 yml，重启回退到配置值，避免配置文件被应用写坏） | 改目录后列表立即变化；重启后回到 yml/env 值 |
| T2.3 设置页入口 | 设置页「公共 Skill」区：显示当前目录、可修改、重扫按钮、扫描数量展示 | 页面可查看/修改目录并重扫 |
| T2.4 目录异常提示 | 目录不存在/不可读时，接口返回明确提示（而非空列表） | 填错目录时前端给出「目录不存在或不可读」 |

## 四、依赖序

B1、B2 相互独立，可并行；均不依赖 V2.1.0 沙箱。
建议交付序：B2（改动小、风险低） → B1。

## 五、Non-Goals（本版明确不做）

沙箱隔离执行（→ V2.1.0）、多租户计费、Starter SDK、Helm、子 Agent 再派发、
Skill 内容执行（仅提示词注入，安全边界不变）。
