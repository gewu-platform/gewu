> 状态：✅ 已完成（tag `v2.4.0`，后端 peels `fdc4d0c` / 前端 `e10834b`）
> 基线：v2.3.0（tag 后端 `5c1519c`）

> 来源：`docs/plan/ROADMAP.md` V2.4.0 批次（六维度能力审计产出）

## 一、一句话定位

v2.4.0 = **沙箱深化 + 审计**：把沙箱从「只有 calculator 一个硬编码分支」
扩展为「适配器可注册的开放结构」，并给管理面操作补上审计留痕。

## 二、为什么现在做

| 事实 | 证据 |
|---|---|
| 沙箱适配器硬编码 | `SandboxRunner.runTool` 内 `if ("calculator".equals(toolName))` 单分支 |
| 新增工具成本高 | 每加一个沙箱工具都要改 Runner 核心类 |
| 管理面无审计 | 谁改了 Agent 定义/模型密钥/插件，无任何留痕（六维度审计缺口） |

## 五、验收结果

- 沙箱：`SandboxAdapter` 接口 + 2 个适配器；未注册工具 fail-closed；`SandboxAdapterRegistryTest` 6 条通过
- 审计：`audit_log` 建表并 Flyway 迁移成功；5 类覆盖抽查通过；
  端到端实证 `provider.create` 的 `apiSpecialKey` 落库为 `***`；
  `session.clear` / `session.delete` 正确留痕（actor=admin，ip=127.0.0.1）
- 测试：**75/75 全绿**
- C3：评估结论文档化——**容器级实施延后**，触发条件明确

## 六、C3 评估结论摘要

| 项 | 结果 |
|---|---|
| 本机容器运行时 | `docker` / `podman` / `nerdctl` **全不可用**（Docker 引擎已损坏），无法实证 |
| 进程级已覆盖 | 进程隔离、超时强杀、`-Xmx` 上限、表达式白名单、审计留档、traceId 父子透传 |
| 容器级实质增量 | 仅三项：文件系统隔离、网络隔离、内核级隔离 |
| 判定 | 当前沙箱只跑受白名单约束的表达式，三项增量对应的「执行不可信第三方代码 / 多租户隔离」场景尚未出现 → **实施延后** |
| 触发条件 | 需跑不可信第三方代码 / 多租户隔离 / 部署环境提供可用容器运行时 |

## 七、Non-Goals（本版明确不做）

容器级沙箱实施（仅评估）、蓝绿发布、K8s/Helm、多租户计费、Starter SDK、
子 Agent 再派发、API `/v1` 前缀。

## 八、决策记录

- 2026-11-02：沙箱适配器采用「接口 + 构造注入注册表」，而非在 Runner 内堆 `if` 分支
- 2026-11-02：审计 detail 对密钥类键名一律掩码 `***`（防明文入库），
  长度上限 2000，旁路失败只 WARN 不阻断业务
- 2026-11-02：审计写操作与业务解耦——审计失败绝不回滚或阻断主流程
- 2026-11-02：容器级沙箱**实施延后**（依据见 C3 评估文档），不做纸面能力
- 2026-11-03：`docs/plan/` 与 `docs/decisions/` 职责分离，C3 评估文档迁入 ADR 目录
