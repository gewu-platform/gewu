# 格物 Gewu · v2.6.0 版本规划

> 状态：**已完成**（2026-11-05 发布，tag v2.6.0）
> 基线：v2.5.0（tag 后端 `32a6580` / 前端 `5f71a39`）
> 日期：2026-11-05 立项并完成
> 来源：需求来源为国际化适配评估；技术方案参考主流开源 AI 项目通行做法（UI 层 i18n + 仓库级双语 README）

## 一、一句话定位

v2.6.0 = **前端整体双语化（i18n）** + **仓库级英文文档**。先仅增加英文版，后续语言按同一机制扩展。

## 二、方案取舍

| 方案 | 评估 | 结论 |
|---|---|---|
| 双仓库（gewu-en） | 代码翻倍维护，缺陷同步成本高 | 不采用 |
| 仅文档双语 | 不满足 UI 国际化目标 | 不采用 |
| UI 层 i18n（vue-i18n 语言包 + 切换器）+ 仓库级英文 README | 主流做法，默认 zh-CN 老用户零感知 | **采用** |

范围说明：后端异常消息/日志本次不迁移——错误码由前端 i18n 层映射展示是行业惯例，
后端消息面向开发者；语言协商（Accept-Language）留待后续按需补充。

## 四、验收情况

- 语言包两包键级一致（161/161，键级递归比对）
- 视图迁移点位键全消费（键存在性判定，排除注释行误报）
- npm run build 通过；script 区无模板专用 $t 残留；无 TS 语法混入
- 默认语言 zh-CN，现有用户零感知；en-US 用户按浏览器语言自动进入英文界面

## 五、实施教训（沉淀）

- 语言包追加快捷脚本在嵌套对象上定位失准（两度引发语法错误）——整文件重建为可靠路径
- SFC 根组件包 ConfigProvider：闭合标签须按首个 `</template>` 插入（按文件末尾匹配会失配）
- script 区不得使用模板专用 `$t`（组合式下用 `t()`）；import 函数名避免与本地 ref 同名（TDZ）

## 六、Non-Goals

- 后端消息层迁移、更多语种、语言协商中间件（按需触发）
- 文档套件全量英文翻译（README 先行，docs/ 随演进补齐）
