# 格物 Gewu · v2.1.0 版本规划

> 状态：draft（2026-10-30 老板拍板三步路线之第三步：打 v2.0.0 tag → v2.0.1 补缺口 → 立 v2.1.0 做沙箱）
> 基线：v2.0.1（插件工具白名单生效 + Skill 目录可配置）
> 日期：2026-10-30

## 一、一句话定位

v2.1.0 = **工具执行沙箱隔离**：给「外部插件 / 危险内置工具」套上进程级隔离与超时熔断，
把 R3 打开的外部执行面重新关进笼子。

## 二、为什么现在做（风险实证）

| 事实 | 证据 |
|---|---|
| 工具执行**无任何隔离** | `ToolRegistry.execute()` 直接 `executor.execute(request, null)`，无超时、无权限边界、无资源限制 |
| 内置已有**动态执行面** | `CalculatorTool` 用 `ScriptEngineManager().getEngineByName("JavaScript")` 直接 `engine.eval(js)`（L24/L35） |
| R3 后执行面**外扩** | 外部 MCP server 的工具经 `McpClientHolder` 桥接进 ToolRegistry 后，与内置工具同权执行；白名单（v2.0.1）只能限制「哪些能进」，管不了「进来后干什么」 |

结论：**v2.0.1 的白名单是准入控制，v2.1.0 的沙箱是执行控制**，两者互补，缺一不可。

## 三、需求 → 批次映射

### B1 执行风险分级与策略

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 风险分级 | 工具按来源/能力标注风险级：`builtin-safe`（datetime/timezone）、`builtin-dynamic`（calculator 走 eval）、`external`（MCP 桥接工具）、`dangerous`（显式标记） | 每个工具可查到风险级；MCP 桥接默认 `external` |
| T1.2 策略配置 | AgentConfig / 全局配置支持：按风险级决定执行方式（直执行 / 沙箱 / 禁用） | 配置为「external 必须沙箱」时，外部工具走沙箱路径 |
| T1.3 审批联动 | `dangerous` 级默认需审批（复用现有 `ToolApprovalGateway`），审批通过后仍受沙箱约束 | 未审批的 dangerous 调用被拦截 |

### B2 沙箱执行运行时

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 进程隔离 | 沙箱工具调用转到独立子进程执行（与 JVM 主进程隔离，崩溃不影响主服务） | 子进程崩溃/死循环不影响主进程存活 |
| T2.2 超时熔断 | 每次调用带超时（默认可配），超时强杀子进程并返回明确错误 | 构造死循环工具，超时被熔断且有日志 |
| T2.3 资源限制 | 子进程设内存上限、禁用危险能力（按平台能力尽力而为，Windows 用 Job Object / 命令行参数约束） | 超限被终止，无 OOM 拖垮主进程 |
| T2.4 结果回传 | 子进程以结构化方式（stdout JSON / 临时文件）回传结果，失败带原因 | 正常/超时/崩溃三类结果均可区分 |

### B3 内置动态执行面收敛

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T3.1 calculator 收敛 | `ScriptEngine.eval()` 换成受限表达式求值（白名单字符 + 语法解析，或纳入 T2 沙箱） | 传入 `java.lang.Runtime` 之类 payload 被拒，不执行 |
| T3.2 注入防护 | 对外部工具入参做基础校验与长度限制 | 超长/异常入参被拒且记录 |

### B4 可观测与降级

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T4.1 沙箱日志 | 沙箱内调用全量记日志（工具名、耗时、退出码、是否超时） | 日志可查 |
| T4.2 降级开关 | 沙箱不可用时可按策略降级（拒绝执行 或 允许直执行但强告警），默认**拒绝** | 关沙箱后外部工具被拒，不静默直执行 |

## 四、依赖序

B1（分级）→ B2（运行时）→ B3（内置收敛）；B4 贯穿。
B1 可与 v2.0.1 并行起步（分级本身不依赖沙箱实现）。

## 五、Non-Goals（本版明确不做）

多租户计费、Starter SDK、Helm、子 Agent 再派发、容器级强隔离（Docker/gVisor——
本机 Docker 引擎损坏，且引入运维复杂度，首版只做到进程级）。

## 六、决策记录

- 2026-10-30 老板拍板三步路线；前两步（v2.0.0 tag、v2.0.1 缺口）已完成/进行中。
- 首版沙箱定为**进程级**而非容器级：够用、无外部依赖、可在本机验证。
- 沙箱不可用时默认**拒绝执行**（fail-closed），不静默降级为直执行。
