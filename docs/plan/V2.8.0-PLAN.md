# V2.8.0 规划：三大能力域对标优化（Skill / 插件 / Agent）

> 基线：v2.7.0（UI 设计体系化 + 部署边界契约 + 暗色模式 + Skill 目录监听/双路径展示）
> 立项：2026-11-16
> 需求来源：三域能力集成对标评审（对标 Claude Code 与 OpenClaw 的 Skill / MCP 插件 / 子代理编排实践），逐域现状复核后形成差距清单与取舍结论

## 一、现状盘点（三域能力面）

| 域 | 已有能力 | 关键实现 |
|---|---|---|
| Skill | 目录扫描（容忍损坏文件）、提示词包全量注入、Agent 定义勾选启用、运行时改目录、手动重扫、WatchService 自动重扫、双路径展示 | `SkillLibraryService.enrich/list/rescan/startWatcher` |
| 插件 | 登记-桥接-启用心智模型、内置样例、工具白名单（tool_allow）、尽力连接（占位端点保持登记态）、MCP 工具桥接为平台工具 | `PluginRegistryService`、SandboxRunner 适配器注册表（fail-closed） |
| Agent | 工具循环（maxIterations）、审批网关（挂起落库/恢复/拒绝续跑）、一层编排树（master→worker，agent_dispatch 同步回传）、RAG 检索注入（topK 钳制）、micro-compaction（单条工具结果截断） | `AgentService.chatStream/runSubAgent/approveAndExecute` |

## 二、对标分析

| 能力 | 格物现状 | Claude Code | OpenClaw | 差距定性 |
|---|---|---|---|---|
| Skill 加载 | Agent 定义勾选 → system prompt **全量注入** | 元数据索引注入 + 模型按需读全文（渐进披露） | 同（索引 + skills_search/skills_read 按需加载） | **结构性差距**：token 成本随勾选数线性增长（→ R1） |
| Skill 触发 | 仅配置期人工勾选 | 描述匹配自动建议 + 用户显式命令 | 同左 | 中等（R1 的按需取用覆盖主要收益，暂不追平） |
| 会话上下文 | 仅 micro-compaction（单条工具结果截断） | 自动压缩 + handoff 摘要（/compact） | 会话压缩 + 交接文档（compact summary） | **结构性差距**：长会话/工具密集场景 token 累积至模型上限后硬失败（→ R2） |
| 子代理编排 | 一层树、**同步单发**（master 阻塞等待单个 worker） | Task 工具可并行多子代理 | sessions_spawn 后台运行 + 收集器聚合 | **能力缺口**：多子任务串行等待，耗时线性叠加（→ R4） |
| 插件连接生命周期 | 安装时一次性尽力连接，之后无状态跟踪 | /mcp 状态机（connected/disconnected/failed）+ 重连 | 插件 enable/disable/reload 运行时全生命周期 | **能力缺口**：端点中途恢复后需卸载重装才能桥接（→ R3） |
| MCP 传输 | http_sse 单一传输 | stdio / SSE / streamable HTTP | 进程内/外部多形态 | 中等（部署形态以容器网络为主，stdio 收益有限，延后） |
| 审批粒度 | 工具名级（isApprovalRequired(toolName)） | 规则级（按工具+参数模式 allow/deny/ask） | 策略按渠道/命令分层 | 中等（现状可用，参数级为增强，延后） |
| 插件分发 | 内置样例硬编码 | 插件市场/目录检索安装 | 官方 catalog + ClawHub | 中等（分发规模未到，延后） |
| 钩子系统 | 无 | hooks（工具调用前后拦截） | automations（定时/事件触发） | 延后（无明确需求来源） |

## 三、深度分析与取舍

### 3.1 会话上下文管理（差距最大，P0）

现状仅有 micro-compaction（截断单条超长工具结果），无会话级压缩。工具循环每轮携带完整历史 + 全量 skill 注入，长会话与工具密集场景下 token 累积不可控，触顶后请求直接失败，用户无感知无自救手段。对标双方均以「阈值触发摘要压缩 + 交接文档续跑」解决。取舍：压缩摘要由当前会话模型生成（不引入额外模型依赖）；压缩点与会话留档对齐（摘要落库可审计）。

### 3.2 插件连接生命周期（P0）

安装时尽力连接、失败保持登记态是 V2.6.0 的刻意简化（避免占位端点阻塞安装）；但缺状态跟踪意味着「端点中途恢复」这一常见场景（本地 MCP server 重启、网络恢复）无法自愈，必须卸载重装。对标双方均维护连接状态机。取舍：状态轮询探活（周期 + 手动刷新）而非事件订阅——实现简单且覆盖核心场景；桥接工具清单随状态变更增量刷新。

### 3.3 子代理并行派发（P1）

`agent_dispatch` 同步单发，master 派发 N 个子任务耗时 = 各子任务之和。Claude Code 单轮多 Task 并行、OpenClaw 后台 spawn + 收集器。格物的工具循环基于 langchain4j，工具执行在请求线程内，并行化需引入异步执行 + 结果聚合 + 事件流标记（哪个 worker 的 delta）。取舍：并行实现收敛在 dispatch 工具层（批量派发工具 + 等待全部完成 + 结构化聚合回传），不改工具循环骨架；单发工具保留（简单任务零开销）。

### 3.4 编排层级（决策：维持一层）

多层递归派发（子 Agent 再派发）在 OpenClaw 支持（后代树），Claude Code 有限支持。格物 V1.1.0 显式设计为「编排树仅一层」（子执行内 agent_dispatch 双层拒绝）。评估：多层带来循环风险、成本失控、结果聚合复杂度陡增，当前业务场景一层树已覆盖；**维持现状并保留双保险拒绝逻辑**，出现真实多层需求时重评（决策记录）。

### 3.5 Skill 渐进披露（P1，承接 R1）

已立项（见 R1）。补充决策：不引入「按对话内容动态挑选技能」的路由层——R1 的按需取用已把选择权交给模型（与对标方一致），路由层属于过度设计。

## 四、需求与任务拆解

### R1 Skill 渐进披露加载（P1，承接前版立项）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 索引注入模式 | `enrich()` 渐进模式：注入「可用技能索引段」（name/description/取用提示）而非全量指令 | 索引段 token 占用 < 全量 10%；Agent 可经工具取到指令 |
| T1.2 指令获取工具 | 内置工具 `skill_instructions(id)`：返回完整指令段（复用工具循环与审批机制） | 对话中按需调用；内容仅进提示词不执行（T2.4 边界不变） |
| T1.3 模式切换阈值 | 单 Agent 勾选数 ≥ 10 或估算注入 > 4k token 自动启用渐进模式，其余保持全量（确定性优先）；缺省向后兼容 | 两模式行为符合各自验收 |
| T1.4 管理台可见性 | Agent 控制台显示当前加载模式与注入 token 估算 | 用户可预判 prompt 成本 |

### R2 会话级上下文压缩（P0）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 阈值触发压缩 | 会话 token 估算超阈值（默认 60% 模型窗口）时，对历史消息生成摘要替换原文（摘要由当前模型生成） | 压缩后上下文降至阈值以下；对话连续性不中断 |
| T2.2 交接文档 | 压缩时产出结构化交接（任务目标/已做决策/未完事项/关键工具结果），摘要 + 交接一并注入 | 压缩后 Agent 仍能引用此前关键结论 |
| T2.3 留档与可见性 | 压缩事件落会话留档（时间点/触发原因/token 前后对比）；前端会话时间线展示压缩标记 | 用户可感知何时压缩、省了多少 |

### R3 插件连接状态机（P0）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T3.1 状态跟踪 | 插件桥接增加连接状态（connected/disconnected/error）与最近探活时间；周期探活（默认 60s，可配） | 状态与实际连通性一致 |
| T3.2 运行时重连 | disconnected/error 状态下周期重试 + 手动「重连」操作；恢复后桥接工具清单增量刷新（无需卸载重装） | 端点恢复后 60s 内自动恢复桥接 |
| T3.3 UI 状态标识 | 插件仓库表格状态列区分「已安装/已桥接/端点不可达」，不可达行给出原因与指引 | 用户可区分安装态与连通态 |

### R4 子代理并行派发（P1）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T4.1 批量派发工具 | 新增 `agent_dispatch_batch`（workers[] + tasks[]）：并行执行全部子任务（线程池，复用一层树约束与免审批语义） | N 个子任务耗时 ≈ max(子任务) 而非求和 |
| T4.2 结构化聚合回传 | 各 worker 结果以结构化块（workerId/状态/结论）聚合回传 master；失败 worker 单独标注不阻断整体 | master 可按 worker 引用结果 |
| T4.3 会话树时间线 | 前端派生会话时间线并行任务分组展示（同一批次归组） | 用户可对照并行批次与各自产出 |

### R5 审批参数级策略（P2，评估项）

按工具+参数模式配置 allow/deny/ask（如 `search.query: allow`、`write_file.*: ask`）。当前工具名级策略可用，参数级在出现误放行/过审场景后再排期。

### R6 插件目录与 stdio 传输（P2，评估项）

官方目录检索一键安装（对标 catalog）；stdio 本地进程传输（对标 Claude Code）。触发条件：插件分发规模扩大 / 出现必须本地进程形态的插件需求。

## 五、非目标与决策记录

| 决策 | 理由 |
|---|---|
| 多层递归编排不做 | V1.1.0 显式一层设计；循环风险/成本失控/聚合复杂度陡增，当前场景一层已覆盖；出现真实多层需求时重评 |
| 动态技能路由层不做 | R1 按需取用已将选择权交模型，与对标方一致；路由层属过度设计 |
| Hooks/automations 系统延后 | 无明确需求来源 |
| MCP resources/prompts 完整桥接延后 | 当前 resources 已以工具形态桥接，prompts 无使用场景 |
