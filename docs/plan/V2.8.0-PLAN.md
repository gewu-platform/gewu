# V2.8.0 规划：Skill 渐进披露加载

> 基线：v2.7.0（UI 设计体系化 + 部署边界契约 + 暗色模式）
> 立项：2026-11-16——skill 加载机制架构演进（对齐 OpenClaw / Claude Code 的渐进披露实践）

## 一、背景

当前实现（V2.0.0 R2/T2.2）：Agent 定义勾选 skillIds → 对话构建 system prompt 时**全量注入**已勾选技能的指令段（`SkillLibraryService.enrich`）。模型根据注入内容自行参考。

该模式在 skill 少、Agent 专属勾选场景下合理（确定性高、无额外往返）。但对齐业界实现（OpenClaw / Claude Code 的 progressive disclosure）后发现演进空间：二者均为「**元数据索引注入 + 模型按需取全文**」——启动时只注入 name/description 索引，模型判断相关后通过工具读取完整指令段。

触发本次评估的实测：单 Agent 勾选 skill 增多后，全量注入的 token 成本线性增长；索引模式可将固定成本压缩至索引段大小。

## 二、需求

| # | 需求 | 说明 |
|---|---|---|
| R1 | Skill 渐进披露加载 | enrich 时仅注入「name + description」索引段；新增内置工具按需取完整指令段 |

## 三、任务拆解

### R1 渐进披露（T1.x）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 索引注入模式 | `enrich()` 新增渐进模式：注入「可用技能索引段」（name/description/调用提示）而非全量指令 | 索引段 token 占用 < 全量的 10%；Agent 可通过工具取到指令 |
| T1.2 指令获取工具 | 新增内置工具 `skill_instructions(id)`：返回该 skill 的完整指令段（复用现有 tool 循环与审批机制） | 模型可在对话中按需调用；内容仅进提示词不执行（T2.4 边界不变） |
| T1.3 模式切换阈值 | Agent 定义新增可选配置：单 Agent 勾选数 ≥ 10 或估算注入 > 4k token 时自动启用渐进模式，其余保持全量注入（确定性优先） | 两种模式行为符合各自验收；配置缺省向后兼容 |
| T1.4 管理台可见性 | Agent 控制台显示当前加载模式与注入 token 估算 | 用户可预判 prompt 成本 |

## 四、非目标

- 不做按对话内容动态挑选技能的路由层（模型自行判断是否调用 skill_instructions 已覆盖主要收益）
- 不改 T2.4 安全边界（SKILL.md 内容仅提示词注入，不执行）

## 五、已实施的前置能力（V2.7.0 收尾随附，2026-11-16）

| 能力 | 说明 |
|---|---|
| Skill 目录文件监听 | WatchService 递归监听 + 1.5s 防抖自动重扫（目录切换自动重启监听） |
| 双路径展示 | GET/POST `/settings/skills/dir` 响应新增 `hostDir`（`GEWU_SKILLS_DIR_HOST` 透传）；前端「扫描目录」直接显示配置的宿主机目录，容器部署下运行时切换前弹确认 |
| compose 透传 | `GEWU_SKILLS_DIR_HOST` 传入容器（仅展示用途） |
