## 三、批次与任务

### C1 父子会话（承接 v1.0.1 B4，V2.0.0 多 Agent 的会话地基）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 数据模型 | `chat_session` 加 `parent_session_id VARCHAR(64)`（init.sql 幂等追加 + COMMENT）；ChatSession 实体/DTO 透出 | 字段就位；存量 NULL 兼容 |
| T1.2 派生流程 | `POST /api/chat/session/{id}/derive`：子会话克隆父 systemPrompt + context_summary（无则取最近 N 条未压缩消息做机械摘录，预算截断）；父子独立演进 | 派生后子会话可独立对话；父会话不受影响 |
| T1.3 树形展示 | 会话列表 DTO 带 parentSessionId；前端同组内父→子缩进树（配合 B2 分组） | 树形正确、折叠可用 |
| T1.4 自动回传 | 子会话回复完成（done）时后端自动生成结果摘要（finalAnswer + toolsUsed，截断保护），以 system 角色消息（前缀「[子会话结果]」）写入父会话；防循环：只向上一层 | 子会话完成后父会话下一轮可自然引用结论，无需人工操作 |

### C2 checkpoint 持久化（Agent 执行态落地）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 数据模型 | `agent_execution` 表（id / session_id / agent_id / status / state_json / create_time / update_time），init.sql 幂等 | 建表幂等 |
| T2.2 审批挂起落库 | ToolApprovalGateway 挂起时写 `waiting_approval` 行（state_json 含 toolCallId/toolName/params/agentId/sessionId）；审批/拒绝后行终结（approved/rejected） | 挂起→审批全链路 DB 可追溯 |
| T2.3 重启恢复 | 启动扫描 waiting_approval 行重建内存 pendingApprovals；前端能重新拉到待审批项 | 杀进程重启后审批流可继续，无需重发原请求 |
| T2.4 超时清理 | 过期挂起行定时标记 expired（对齐 token 有效期语义） | 无僵尸行 |

### C3 MCP 客户端（工具生态入口，V2.0.0 插件仓库的地基）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T3.1 依赖与传输 | 引入 langchain4j-mcp；支持 HTTP(SSE) 传输连接外部 MCP server | 可连通一个公共 MCP server |
| T3.2 配置模型 | `mcp_server` 表（name / transport / endpoint / enabled）+ 设置页管理 | CRUD + 启停即时生效 |
| T3.3 工具桥接 | MCP 工具注册进 ToolRegistry（命名空间 `mcp:{server}:{tool}`），审批策略沿用（默认需审批） | Agent 对话可调用 MCP 工具并返回结果 |
| T3.4 文档 | docs/MCP.md（filesystem / fetch 等公共 server 配置样例） | 按文档可复现 |

## 四、依赖序与里程碑

C1 → C2 → C3（C1 为 V2.0.0 R1 前置，最高优先；C2/C3 相互独立）。
