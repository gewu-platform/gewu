# 格物 Gewu · v2.5.0 版本规划

> 状态：draft（待开工；E1/E2 为 P0，优先于 D1-D4）
> 基线：v2.4.0（tag 后端 `fdc4d0c` / 前端 `e10834b`）
> 日期：2026-11-03 立项
> 来源：`docs/plan/ROADMAP.md` V2.5.0 批次 + 2026-11-02 竞品分析取舍

## 一、一句话定位

v2.5.0 = **评测可复现与信任声明（P0）** + **产品化按需项（P2，触发制）**。
P0 两项来自竞品分析，低成本且直接提升「可信度」；P2 项等触发条件出现再做。

## 二、为什么现在做（P0 依据）

| 事实 | 影响 |
|---|---|
| B2 评测现走工具路径（calculator，确定性 OK） | 一旦扩展到 LLM 生成质量评测，采样随机性会让分数不可复现 |
| 评测基线不可复现 | 回归对比失去意义——改 prompt/换模型后无法判断是否变差 |
| 数据流向未声明 | 代码本已本地存储，但未说清；开源口碑与面试讲解都吃亏 |

## 三、任务拆解

### E1 评测确定性约束（P0，借鉴 DeepInfer deterministic sampling）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| E1.1 固定采样参数 | 评测执行器调用 LLM 时强制 `temperature=0` 并传固定 `seed`（厂商 API 支持时） | 同一评测集连续跑 2 次，分数完全一致 |
| E1.2 可复现断言 | 评测报告输出 seed / temperature / model 指纹 | 报告含完整可复现元信息 |
| E1.3 基线文件化 | 评测结果可落基线 JSON（供 `BASELINE_FILE` 对比，衔接 B2.3 已留扩展点） | `BASELINE_FILE=... mvn test` 能报出分数回退 |
| E1.4 说明文档 | 在 eval README 写明「LLM 类评测需确定性才有回归意义」 | 文档可读 |

### E2 数据流与最小化声明（P0，借鉴 OpenClaw 遥测姿态）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| E2.1 README 声明 | 新增「数据流向」章节：数据存本地、凭据不出机、默认无外发遥测 | 章节存在且准确 |
| E2.2 外发清单 | 列出实际外发项（模型厂商 API 调用、可选诊断导出） | 清单完整 |
| E2.3 开关说明 | 若后续引入任何统计/版本检查，必须默认关闭且可配置 | 规则写入文档 |

### P2 产品化按需项（触发条件出现再做，本版不排期）

| 编号 | 内容 | 触发条件 |
|---|---|---|
| D1 手动蓝绿 | docker-compose 双实例 + nginx upstream 权重切换 + 回滚脚本 | 出现真实持续流量或 SLA 要求 |
| D2 K8s/Helm | 编排清单、滚动更新、探针、HPA | 多实例部署成为常态（当前明确不建议） |
| D3 框架级 SPI | `ToolProvider`/`LlmVendorAdapter` 抽象 + 条件装配 | 第三方开发者接入或扩展点 ≥8 个 |
| D4 API `/v1` 前缀 | 版本化路由 + 兼容层 | 对外承诺 API 稳定性 |
| ~~D5 依赖漏洞扫描~~ | ✅ 已完成（`2cca381`，CI 报告型） | — |

## 四、依赖序

E1、E2 相互独立，可并行；均不依赖 D1-D4。
建议交付序：E2（半小时）→ E1（半天）。

## 五、Non-Goals（本版明确不做）

D1-D4 产品化项（触发制）、多租户计费、Channels 消息平台接入、
Plugin SDK（等第三方开发者）、结构化输出能力探测（2026-11-03 裁定不做——
无对应需求，且 function calling 已是更靠前保障）。
