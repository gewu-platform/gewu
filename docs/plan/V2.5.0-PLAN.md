> 状态：confirmed；**E1/E2 已完成**（提交 `2c45ab4`，2026-11-03 实测验收通过）；M1/M2 进行中；D 组为触发制

## 一、一句话定位

v2.5.0 = **评测可复现与信任声明（P0）** + **多模态对话（P1）** + **产品化按需项（P2，触发制）**。
P0 两项低成本且直接提升「可信度」；M1/M2 补齐已预留契约的图片对话与文件解析能力。

## 二、为什么现在做（P0 依据）

| 事实 | 影响 |
|---|---|
| B2 评测现走工具路径（calculator，确定性 OK） | 一旦扩展到 LLM 生成质量评测，采样随机性会让分数不可复现 |
| 评测基线不可复现 | 回归对比失去意义——改 prompt/换模型后无法判断是否变差 |
| 数据流向未声明 | 代码本已本地存储，但未说清；开源口碑与面试讲解都吃亏 |

### M1 图片对话（P1）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| M1.1 对话附件上传 | `POST /api/chat/upload`（multipart）：经存储中间件写入，白名单 jpg/png/webp/gif、≤10MB，返回访问 URL | 上传成功可访问；超限/类型不符报 400 |
| M1.1.1 存储抽象 | `FileStorage` 接口 + MinIO 实现（S3 兼容 SDK）；统一约定：**所有上传文件写入 MinIO，库表仅存访问链接**；配置项 `gewu.storage.*`（endpoint/bucket/accessKey/secretKey）；知识库现有本地磁盘写入（`uploads/knowledge/`）一并迁移 | 上传与读取均走 MinIO；compose 含 minio 服务与数据卷；单测覆盖上传/下载/删除 |
| M1.2 消息链路消费 | `ConversationService` 用 LangChain4j `ImageContent` 构造多模态 UserMessage（base64 data URI）；`imageUrls` 随消息落库；同步与流式两路径均支持 | 视觉模型能描述所发图片；历史重载后图片仍在 |
| M1.3 能力门禁 | 模型配置增加 `capability` 标记；非视觉模型发图时返回可读提示而非模型侧报错；`/chat/mode` 返回真实能力 | 纯文本模型发图得到明确提示 |
| M1.4 前端粘贴与附件 | `ChatView` 输入框加 `@paste` 监听（`clipboardData.items` 抓取图片）+ 附件按钮 + 缩略图预览/删除 + 历史消息渲染图片 | 截图后 Ctrl+V 直接进入输入框，发送后模型可见 |

**存储选型（2026-11-03 已定）**：MinIO —— S3 兼容 API、单二进制自部署、与 E2「数据存本地」
信任声明一致；公有云对象存储与该声明冲突，不选。

**统一约定**：所有上传文件（知识库文档、对话附件）一律写入 MinIO；
数据库仅存文件访问链接（URL / object key），不存文件本体。
实现为薄抽象 `FileStorage`（当前实现为 MinIO），保留接口以便将来替换。

**存量迁移**：知识库现有上传写本地磁盘 `uploads/knowledge/`（`KnowledgeBaseService.UPLOAD_DIR`），
本次一并迁移到 MinIO，并废弃该本地目录。

**前置条件**：M1 生效要求激活模型为视觉模型（qwen-vl / gpt-4o 等）；
纯文本模型下发图由 M1.3 门禁拦截。

## 四、依赖序与交付节奏

E1、E2 相互独立可并行；M1 依赖存储抽象（M1.1.1）与能力门禁（M1.3）；M2 复用 M1 的上传端点。
均不依赖 D1-D4。建议交付序：**E2（半小时）→ E1（半天）→ M1（后端 1 天 + 前端 1 天）→ M2（半天）**。

## 五、Non-Goals（本版明确不做）

D1-D4 产品化项（触发制）、多租户计费、Channels 消息平台接入、
Plugin SDK（等第三方开发者）、结构化输出能力探测（2026-11-03 决策：不做——
无对应需求，且 function calling 已是更靠前保障）。
