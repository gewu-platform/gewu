# 格物 Gewu · v2.0.0 版本规划（多 Agent 能力生态）

> 立项：2026-10-29 老板拍板。前置：V1.1.0 收官（父子会话 / checkpoint / MCP 客户端）。
> 本版把产品从「单 Agent + 工具」升级为「多 Agent 编排 + 能力生态」。

## 一、一句话定位

主 Agent 规划编排、子 Agent 执行落地的多 Agent 体系；Agent 能力来源从「内置工具」扩展为「内置工具 + 公共 Skill 库 + 插件仓库」。

## 二、需求 → 批次映射

| # | 需求（原文） | 批次 |
|---|---|---|
| 1 | 支持多 Agent 调用（主从 Agent：主 Agent 负责规划和编排子 agent，子 agent 负责具体功能点或功能操作的实现和执行） | R1 多 Agent 主从编排 |
| 2 | 支持接入或读取公共配置的 skill（从默认目录 `C:\Users\25333\.agents\skills`） | R2 公共 Skill 库 |
| 3 | 支持接入常用插件仓库的 plugin 插件 | R3 插件仓库（含 MCP 生态） |

## 三、批次与任务

### R1 多 Agent 主从编排（建在 V1.1.0 C1 父子会话之上）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T1.1 编排数据模型 | `agent_definition` 增角色维度：`role`（master/worker）+ `allowed_workers`（主可调度的子清单）；子 Agent 保持现有单 Agent 语义 | 主从定义可建、可启停 |
| T1.2 派发工具 | 内置 `agent_dispatch(workerName, task)` 工具（白名单挂 AUTO_APPROVED，参数与目标可审计）：主 Agent 对话中规划→调用→为目标子 Agent 派生独立子会话（C1 T1.2 派生流程）执行任务 | 主 Agent 一轮对话内完成「规划→派发→收结果」 |
| T1.3 结果回传 | 复用 C1 T1.4 自动回传：子会话 done 后摘要（finalAnswer + toolsUsed）回写父会话；主 Agent 下一轮自然引用；深度限制一层，防循环 | 多步任务（如「用计算器算 A，再把结果写入知识库检索验证」）全程自动 |
| T1.4 执行留档 | 派发链路入 llm_call_log（复用 user_id 接线）；父/子会话在会话树中可见（C1 T1.3） | 报表可观测主从调用量 |
| T1.5 前端 | 会话树渲染主从链路标记；Agent 管理页支持角色配置 | 界面可配可查 |

### R2 公共 Skill 库（从 `C:\Users\25333\.agents\skills` 读取）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T2.1 Skill 解析 | 扫描默认目录下 `*/SKILL.md`（YAML frontmatter：name/description；正文为技能指令），容忍损坏文件跳过 | 目录全量解析，样例 skill 元数据正确 |
| T2.2 注册与生效 | Skill 以「提示词包」形态挂载：Agent 定义可勾选启用 skills；对话构建 system prompt 时注入启用技能的指令段 | 启用某 skill 后 Agent 行为按技能指令改变 |
| T2.3 管理界面 | 设置页 Skill 列表（名称/描述/启用状态），目录变更支持手动重扫 | 增删 skill 文件后重扫即生效 |
| T2.4 安全边界 | SKILL.md 内容仅作提示词注入，不执行其中任何指令；目录只读 | 恶意内容无法触发代码执行 |
| T2.5 可配置目录 | 默认 `C:\Users\25333\.agents\skills`，env/设置可改（部署机适配） | 改目录后重扫生效 |

### R3 插件仓库（常用 plugin 接入）

| 任务 | 内容 | 验收标准 |
|---|---|---|
| T3.1 插件形态定义 | 首版插件=外部 MCP server（复用 V1.1.0 C3 客户端）+ 插件清单（name/描述/endpoint/传输/工具白名单） | 形态文档化（docs/PLUGIN.md） |
| T3.2 插件仓库管理 | `plugin_registry` 表 + 设置页：浏览/安装（登记）/启停/卸载；支持从常用仓库清单一键添加（预置几个公共 MCP server 样例） | 安装启停即时生效 |
| T3.3 工具桥接 | 插件工具进 ToolRegistry（命名空间沿用 `mcp:{server}:{tool}`），审批策略默认需审批 | Agent 可调用插件工具完成真实任务 |
| T3.4 常用仓库接入 | 内置样例仓库配置（如 filesystem / fetch / time 等官方参考 server），文档给自建 server 接入样例 | 按文档接入一个自建插件全链路 |

## 四、依赖序

V1.1.0（C1 → C2 → C3）→ R1（依赖 C1 派生/回传）→ R3（依赖 C3 客户端）；R2 独立可并行。
建议交付序：V1.1.0 收官 → R1 → R2 ∥ R3。

## 五、Non-Goals（本版明确不做）

沙箱隔离执行 / 多租户计费 / Starter SDK / Helm / 子 Agent 再派发（编排树仅一层）。

## 六、决策记录

- 2026-10-29 老板拍板：三大需求由「v2.0 触发制」正式立项为 v2.0.0；V1 剩余功能（V1.1.0-PLAN）先行。
- ToolApprovalGateway 中既有 `agent_dispatch` 白名单命名为本版 T1.2 预留，沿用。
