# 格物 Gewu · v2.3.0 版本规划

> 状态：✅ 已完成（tag `v2.3.0`，后端 peels `5c1519c` / 前端 `e10834b`）
> 基线：v2.2.0（tag 后端 `e692472`）
> 日期：2026-11-02 开工、2026-11-02 收官
> 来源：`docs/plan/ROADMAP.md` V2.3.0 批次（六维度能力审计产出）

## 一、一句话定位

v2.3.0 = **评测与质量底线**：把「全靠人工冒烟」的项目，补上测试基线、
LLM 评测闭环与版本治理三块底座——让后续每次改动有回归可依。

## 二、为什么现在做（审计证据）

| 事实 | 证据 |
|---|---|
| 测试文件为 0 | `gewu-web/src/test` 目录不存在 |
| 无评测集 | 无 eval 相关资源与执行器 |
| 版本治理有缺口 | tag 与规划文档齐全，但无 `CHANGELOG.md`、DB 迁移靠手写 SQL |

结论：可观测（v2.2.0）解决了「看清」，v2.3.0 解决「敢改」。

### 测试与评测抓出的 3 个真实产品缺陷

| # | 缺陷 | 发现方式 | 修复 |
|---|---|---|---|
| 1 | 幂运算 `2^10` 从实现起就是坏的——Nashorn 不支持 `**` 运算符，旧实现 `replaceAll("^","**")` 直接语法报错 | B1 `CalculatorToolTest` | 改写为 `Math.pow(a,b)`，支持括号/嵌套操作数扫描；整数浮点结果归一 `.0` 尾 |
| 2 | 链式幂 `2^3^2` 改写丢失函数名前缀 → `Math.powMath.pow(2,3)` TypeError | B2 评测集 calc-016 | 左操作数扫描向左扩展捕获完整调用标识符 |
| 3 | 超 int 范围整数输出科学计数法（`999999*999999` → `9.99998000001E11`） | B2 评测集 calc-018 | `BigDecimal.toPlainString` 归一（double < 2^53 范围内精确） |

> 这三个缺陷人工冒烟从未覆盖——正是引入测试与评测的直接价值。

## 五、验收结果

- `mvn test`：**75/75 全绿**（含 21 条评测用例）
- Flyway 运行时验证：Schema history 创建 → baselined v1 → Migrating v2 → 成功；二次启动识别「已是最新，无需迁移」（幂等成立）
- 已有 `sys_user_setting` 表的库重复执行不报错
- CI 按 2026-11-02 拍板**保留 `-DskipTests`**，本地 `mvn test` 为质量闸门

## 六、Non-Goals（本版明确不做）

CI 改为强制跑测试（拍板保留 `-DskipTests`）、性能压测、覆盖率门槛、
多租户场景下的数据隔离测试。

## 七、决策记录

- 2026-11-02 老板拍板：测试框架用 `spring-boot-starter-test`；测试按被测类镜像包结构；
  评测集放 `src/test/resources/eval/*.yaml`；CI **保留** `-DskipTests`
- 2026-11-02：Flyway 契约定为「`init.sql` 仍是建库真相源，Flyway 只管 V2+ 增量，
  增量 SQL 必须幂等」——避免破坏既有单文件真相源约束
- 2026-11-02：评测执行器设计为「报告型」（单条失败不中断其余用例），
  评测语义是出报告而非断路
