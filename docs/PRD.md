## 1. 一句话定位

**面向 Java 技术栈企业的开源自部署 Agent 平台**——Docker Compose 起服务，网页配置模型 Key、上传知识库、零代码创建 Agent，即配即用，支持基于 API 与扩展点的企业二次开发。

**市场洞察**：Dify / FastGPT / RagFlow 等 Agent 平台清一色 Python 栈。大量国企、银行、制造业企业的运维与二开团队只维护 Java 技术栈。「Java 企业的自己人 Agent 平台，二开零语言切换成本」是真实空白。

**竞品速览**：

| 平台 | 技术栈 | 二开语言 | 特长 |
|---|---|---|---|
| Dify | Python | Python | 全功能 LLM 应用平台，工作流编排强 |
| FastGPT | Node/TS | TS | 知识库问答见长 |
| RagFlow | Python | Python | 深度文档解析见长 |
| **格物 Gewu** | **Java / Spring Boot 3 + LangChain4j** | **Java** | Java 团队自部署与二开零语言切换，差异化卡位 |

**Slogan（备选）**：
- 中文：格物致知，一键智能
- 英文：Gewu — The Self-Hosted Agent Platform for Java Teams

## 2. 设计目标（唯一锚点）

```
企业拿到的产品
 ├─ 🚀 部署即用      → docker compose up，无源码依赖
 ├─ 🔑 配置即用      → 界面配模型 Key，改配置不重编译、不重启
 ├─ 📚 知识即用      → 上传文档 → 自动索引 → Agent 引用回答
 └─ 🔧 二开友好      → 清晰扩展点 + API 文档 + 教程
```

## 3. 目标用户

| 角色 | 诉求 |
|---|---|
| 企业 IT / 运维 | 快速部署、管账号、看用量，出问题好排查 |
| 业务开发者 | 二开集成：加自定义工具、接自有系统 API |
| 最终业务用户 | 网页对话、查知识库，不需要懂 AI |

## 4. 核心用户旅程（验收即按此走）

1. 运维：装 Docker → `docker compose up -d` → 打开网页
2. 管理员：初始账号登录 → Settings 页配置模型（endpoint + key + 模型名）→ 保存即生效
3. 知识管理员：上传产品手册 / 制度文档 → 等待索引完成 → 用检索测试台验证命中
4. 业务负责人：从模板创建 Agent（如「知识库问答」）→ 绑定知识库与工具 → 启用
5. 员工：网页直接对话，答案引用知识库片段；用量在管理页可见

**北极星指标**：① 全新机器 30 分钟完成部署到首次成功对话；② 外部开发者半天内按文档完成自定义工具接入；③ 上传文档到 Agent 正确引用 ≤10 分钟。

## 5. 功能需求

### 5.1 v1.0 范围（P0）

| # | 模块 | 需求 | 验收标准 |
|---|---|---|---|
| F1 | 部署工程 | 后端 Dockerfile（分层 fat jar）+ 前端 Dockerfile（nginx）+ `docker-compose.yml`（app + PG/pgvector + web）+ `.env.example` + 幂等 init SQL | 全新机器 30 分钟内完成部署到第一次成功对话 |
| F2 | 模型配置中心 | `llm_provider` 表（provider_type=chat/embedding、endpoint/apiKey AES 加密/model 列表/enable）+ Settings 管理页 + 运行时动态生效，**同时覆盖对话模型与 embedding 模型**（替换 yml 硬编码的 Volc 配置） | 网页改配置后下一个请求即用新模型（对话与知识库索引/检索同步生效）；key 密文落库；连错有明确报错提示 |
| F3 | 知识库打磨 | 现有 RAG 复用 + docx/pdf 解析入库 + **检索测试台**（输入问题看命中片段与相似度，辅助调阈值） | pdf/docx/md/txt 四类文件全链路；测试台命中结果与 Agent 引用一致 |
| F4 | Agent 创建向导 | 预置 2~3 模板（知识库问答/客服接待/通用助手）+ 绑定知识库/工具的表单化创建（定义 CRUD 已有，补模板与引导） | 3 分钟内从模板创建可用 Agent |
| F5 | 二开文档 | API 手册（重点写清 SSE 事件契约：eventType/事件字段/审批闭环）+ 「新增一个自定义工具」教程 + 扩展点说明 | 外部开发者按文档独立完成一个自定义工具接入 |
| F6 | 用量可见 | 现有 token_usage / llm_call_log 包装成管理页报表（按天/按用户/按 Agent 汇总）；可选配额开关（超限拒绝，非预扣） | 报表数字与库内记录一致；配额开关生效 |

### 5.2 v1.1 范围（P1）

| # | 模块 | 需求 |
|---|---|---|
| F7 | 上下文压缩 | 工具结果超长截断 + 重复失败折叠（L1.5）；真实 token 用量触发的摘要压缩（L2） |

### 5.3 v2.0 范围（按真实需求触发，默认不做）

多租户与计费体系（预扣/结算/死信队列）· 子 Agent 派生 · 状态图执行器重构 · Docker 沙箱工具执行 · Spring Boot Starter 二开 SDK · K8s Helm Chart

### 5.4 非功能需求

- **兼容性**：SSE 事件契约向后兼容（二开者依赖）；升级只跑幂等 SQL
- **安全**：API Key AES 加密落库；初始管理员强制改密；上传文件类型白名单
- **资源**：单机 8G 内存可跑全栈（compose 形态）
- **可观测**：结构化日志文件（info/error 分级，已有）+ 健康检查端点（已有）
- **测试基线**：核心链路（审批闭环 / RAG 检索 / 配置中心）集成测试随任务交付，CI 保持绿色
- **数据备份**：DEPLOY.md 提供 pg_dump 定时备份与恢复指引（数据库卷 + 上传文件卷）

### 5.5 明确不做（Non-Goals）

SaaS 多集群 · 插件市场 · 移动端 · 工作流编排画布 · LangGraph/Python 双端（技术栈保持纯 Java）

## 6. 现状资产映射（gewu develop @ `bcb7ace`）

**直接复用（约 60% 现成）**：
- RAG 全链路：pgvector 0.8.3 + 异步索引 + 阈值可配 + 多模态 embedding（F3 只差格式与测试台）
- Agent 引擎：function calling 循环 + 审批网关（三态）+ 挂起式续跑 + 15s 心跳
- SSE 契约：delta/thought/action/tool_result/approval_required/rag/done/error/ping 十类事件（F5 的卖点素材）
- 会话与轨迹：chat_session/chat_message + tool_calls JSONB 落库
- 监控记账：token_usage / llm_call_log 双表（F6 数据源现成）
- 前端：ChatView 智能模式、AgentView 管理控制台、知识库三面板、审批卡片、认证体系
- 权限：JWT + ADMIN/MEMBER 两级 + 管理员唯一事实源 AdminAccounts

**需新建（v1.0 工作量所在）**：容器化交付全套（F1）、llm_provider 配置中心（F2）、docx/pdf 解析与检索测试台（F3）、Agent 模板（F4）、二开文档（F5）、用量报表页（F6），以及技术债清偿（HTTP 响应 charset 声明、yml 死配置清理）

**前置拆解**：学习示例模块（ExamplesView + ServiceController + AiServiceLayer）迁回 learn 分支，develop 专注产品化

### 7.3 迭代原则

1. **横向演进逻辑**：v1.0 消除使用门槛 → v1.1 提升智能与韧性 → v2.0 服务规模化，每列是一次可独立验收的发布
2. **契约稳定**：SSE 事件契约跨版本向后兼容，二开者升级不破代码
3. **升级即 SQL**：跨版本升级只跑幂等 SQL，不做数据迁移脚本
4. **触发制后置**：v2.0 各项默认冻结，出现真实企业需求（有人要运营/要接 LangGraph 生态）才解封对应项
5. **i18n**：中文优先；英文界面列为候选，待海外社区真实反馈后启动
